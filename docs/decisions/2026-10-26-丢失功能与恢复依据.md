## 2. L6 加热启动性能与超调优化

负责人描述：原固件优化了 IMU 加热的启动性能和加热超调，`a2cfd16` 的代码里很可能没有这部分。

### 2.1 `a2cfd16` 的实现（作为对照）

`legacy/Libraries/Device/bmi088/Bmi088Heater.{hpp,cpp}`：

- 目标 50 ℃，控制周期 128 ms，PWM 100 Hz；温度高于 65 ℃ 或样本超过 500 ms 未更新时关闭输出。
- 温度低于 45 ℃ 时固定 200‰ 占空比预热；之后 PI 控制（Kp 10、Ki 1、Kd 0，输出与积分上限 300‰），负积分清零。
- 源码注释自述的问题：BMI088 温度寄存器 1.28 s 才更新一次，加上控制周期，反馈盲区约 1.45 s；满功率预热会冲到约 92 ℃；200‰ 预热把过冲压到几度以内；PI"响应慢但过阻尼"。

### 2.2 原固件的运行时证据（只读观察）

2026-10-26 通过 SWD 不停核读取原固件 RAM：

- 加热器对象位于 `0x2400490c`（160 字节，与 `a2cfd16` 的 `Bmi088Heater` 大小相同）。后 32 字节与 `a2cfd16` 的成员顺序一致，已逐秒读取确认：
  | 地址 | 成员 | 读数（恒温状态） |
  |---|---|---|
  | `0x2400498c` | 状态、已初始化、已使能、已收到样本 | 3（恒温调节中）、1、1、1 |
  | `0x24004990` | 目标温度 | 50.0 ℃ |
  | `0x24004994` | 当前温度 | 49.875–50.125 ℃，按 0.125 ℃ 跳动 |
  | `0x24004998` | 占空比（‰） | 9–11 |
  | `0x2400499c` | 温度读取次数 | 每秒约 +25 |
  | `0x240049a0`、`0x240049a4` | 上次样本、上次控制时刻（DWT，480 MHz） | 递增 |
- 前 128 字节在 `a2cfd16` 中是 PID 对象，原固件中却是另一套状态：10 格环形缓冲区（w02–w11，下标 w26）在升温时先冲到约 63 ℃、再缓慢回落，像控制器内部估算的热源侧温度；w30 等于最近一次传感器读数；w31 在 0.5–1.28 s 之间变化，与 BMI088 温度更新周期吻合。推断原固件用模型估算补偿传感器更新慢造成的反馈盲区（详见冷启动数据说明）。
- 恒温时占空比读数只有约 9（若单位为 ‰ 则不到 1%），而 `a2cfd16` 注释记录"10% 稳态 42.4 ℃"。单位是否改变未确认；负责人说明板子自身发热可达 42 ℃ 以上，稳态所需加热功率小是合理的。
- 原固件自动完成的陀螺采集（`test/data/imu/2026_10_26_lost_fw_gyro_capture/`）在陀螺开始工作后约 19 s 开始；冷启动记录中同一采集在 20.7 s 开始，两者一致。

### 2.3 冷启动加热曲线（验收下限）

数据：[`test/data/heater/2026_10_26_lost_fw_coldstart/`](../../test/data/heater/2026_10_26_lost_fw_coldstart/README.md)（2026-10-26，断电约 4 分钟后上电，5 Hz 记录约 15 分钟）。负责人说明这块板即使不接 24 V 也会很快升到 42 ℃ 以上，无法从室温开始记录，因此重点是逼近 50 ℃ 的过程。

| 指标（自 IMU 启动） | 原固件实测 | 重做时的要求 |
|---|---|---|
| 起始温度 | 32.0 ℃（2.3 s 时） | 同等或更低起始温度下比较 |
| 到达 49.5 ℃ | 17.8 s | 不慢于此 |
| 到达 50.0 ℃ | 24.1 s | 不慢于此 |
| 最大过冲 | +0.375 ℃（44.6 s） | 不大于此 |
| 进入并保持 50 ±0.25 ℃ | 111 s | 不晚于此 |
| 稳态波动（最后 300 s） | 49.875–50.125 ℃ | 不大于此 |
| 故障 | 0 | 0 |

`a2cfd16` 的加热实现尚未在同样条件下实测；重做时用同一套工具（`tool/debug/swd_poll.py` + `heater_log_decode.py`）在相同条件下记录新实现，与上表逐项对照。
