## 需要的东西

| 项 | 必需 | 用来检查 |
|---|---|---|
| DM-MC02 + Vllink Basic2（CMSIS-DAP，SWD） | 是 | 烧录、只读探测 |
| 板子供电（XT30 或 USB） | 是 | — |
| 24 V（XT30） | 加热检查必需 | BMI088 加热：不接 24 V 时加热电阻没有电源，温度停在板子自身发热的 40 ℃ 左右 |
| USB 线接板上的 USB 口 | 建议 | USB CDC 状态行与回显 |
| SBUS 接收机（接 SBUS 口）与遥控器 | 可选 | UART 接收与 SBUS 解析 |
| GM6020 或其他会主动发反馈的 CAN 设备 | 可选 | CAN 接收（GM6020 不需要控制帧就发 1 kHz 反馈；电机由板上两路可控 24 V 输出供电，bringup 不打开它们，要经 SWD 写 `GPIOC_BSRR = 0x6000`（PC13、PC14 拉高），复位后恢复关闭；没帧时先读 FDCAN 的 PSR / ECR 区分"线上没信号"与"波特率不对"） |

## 1. 烧录前备份板上固件（只读）

板上现在应是 2026-10-31 烧的 bringup 固件（原固件已存档在 `foray_mcu_archive/2026-10-26_DM-MC02_flash/`）。
按惯例仍先只读备份一次：不停核、不复位，同一会话读两遍并比较。

```bash
mkdir -p ../foray_mcu_archive/<日期>_DM-MC02_flash_before_f2_peripherals && cd $_
openocd -f /mnt/data/projects/foray_mcu/tool/flash/openocd/dm_mc02_cmsis_dap.cfg \
  -c "init" -c "dump_image a.bin 0x08000000 0x100000" -c "dump_image b.bin 0x08000000 0x100000" -c "shutdown" \
  2>&1 | tee openocd_dump.log
cmp a.bin b.bin && mv a.bin DM-MC02_flash_0x08000000_1MiB.bin && rm b.bin && sha256sum *.bin > SHA256SUMS
```

## 3. 上电即可看到的现象

| # | 现象 | 说明 |
|---|---|---|
| 3.1 | 上电约 0.2 s 内蜂鸣器"嘀嘀"两声（2000 Hz、2600 Hz 各 80 ms） | PWM（TIM12）、`hal::init()` 成功、任务运行器在跑 |
| 3.2 | 板载 RGB 灯 1 Hz 闪烁，约 0.5 s 内变绿 | SPI6 异步发送（WS2812）；绿 = IMU 数据在更新；黄 = 只有心跳；红 = 心跳也停了 |
| 3.3 | 接了 24 V 时，约 25 s 后 BMI088 附近微温（50 ℃） | 加热 PWM（TIM3）与温度闭环 |

灯一直红或不亮、蜂鸣器不响：`hal::init()` 或某个能力的 `init()` 失败，固件停在 `Error_Handler`（步骤 4 的 PC 采样会指出）。

## 4. 只读探测（主要判据）

```bash
python3 tool/debug/bringup_probe.py --elf build/arm-debug/firmware_bringup_dm_mc02.elf \
  --gdb $ARM_GCC_ROOT/bin/arm-none-eabi-gdb --log ../foray_mcu_archive/<日期>_F2_onboard/probe.log
```

脚本用 gdb 从 ELF 算出地址（不连目标），再用 OpenOCD 不停核地隔约 1 s 读两次，打印每一项的读数、增量与判定。
速率按两次读数之间 TIM2 走过的时间计算（读取本身也要时间，不按名义间隔），TIM2 用 OpenOCD 的主机毫秒数核对。
`--dry-run` 只打印地址与读取脚本，不连目标。判定项与通过条件：

| 判定 | 通过条件 | 验证的是 |
|---|---|---|
| 时基 | 按主机时钟，TIM2 每秒约 1,000,000 | hal/os 时基 |
| heartbeat 任务 | 每秒约 1000 轮，错过周期 0 | 周期任务 |
| monitor 收到全部心跳 | 最近序号减收到次数为 0 或 1（两者先后读出），丢失 0，乱序 0 | 按 topic 触发、读者优先级高于写者 |
| BMI088 已配置好 | `ready` 为 1、`error` 为 0 | SPI2 异步全双工、BMI088 驱动的配置链 |
| 陀螺 / 加速度计样本 | 每秒约 2000 / 1600 | GPIO 外部中断、SPI DMA、驱动调度 |
| **中断里发布 `bringup.imu_event`** | 每秒发布次数 ≥ 两个数据就绪次数之和（另加 SPI 完成） | **F2 验收：中断里发布 topic** |
| **IMU 任务被中断发布的 topic 叫醒** | 每秒数千轮，等待超时 0 次，延迟超过 200 µs 的 0 次 | **F2 验收：阻塞等待的任务收到中断发布的 topic** |
| BMI088 温度 | 接了 24 V、冷启动 25 s 后在 50 ℃ 附近（脚本只查 20–60 ℃；闭环要另外连续记录，见验证记录的"加热"） | 加热闭环 |
| 各任务剩余栈 | 都大于 32 字 | 任务表的栈够用 |
| CAN 1–3 | `bus_ready` 为 1，Bus-Off 为 0 | FDCAN 启动；接了会发帧的设备时帧数增加 |
| SBUS 端口 | `port_ready` 为 1；接了接收机时每秒约 70–140 帧 | UART5 DMA 接收、SBUS 解析 |
| USB 状态行 | 主机打开串口后每秒约 10 行 | USB CDC 发送 |
| PC 采样 | 16 次都不在 `Error_Handler`、`HardFault_Handler` | 没有卡在错误处理 |

## 5. 人工检查

| # | 操作 | 期望 |
|---|---|---|
| 5.1 | 插 USB，`python3 -m serial.tools.miniterm /dev/serial/by-id/usb-STMicroelectronics_STM32_Virtual_ComPort_*-if00 115200`（或任意串口终端；Vllink 自己也有一个串口，常占 `/dev/ttyACM0`；用户不在 `dialout` 组时先 `sudo setfacl -m u:$USER:rw <设备>`） | 每 0.1 s 一行 `t=… hb=… imu=… q=… g=… a=… T=… sbus=… ch=… fs=…`，格式见 `app/bringup/usb_report.hpp` |
| 5.2 | 在终端里打字 | 字符被原样回显 |
| 5.3 | 静止平放 | `a=` 约 `0.00,0.00,9.81`；`g=` 各轴接近 0；`q=` 的 w 接近 1 |
| 5.4 | 绕竖直轴转板 | `g=` 的 z 分量随转速变化；`q=` 的 z 分量变化 |

| 5.6 | 拔掉 USB 再插上 | 状态行恢复（断开时发送中断算失败，不影响其他任务） |
