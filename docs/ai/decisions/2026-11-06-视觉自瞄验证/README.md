# 2026-11-06 视觉自瞄链路的可行性验证（海康 MV-CS004-10GC）

用一台装在云台上的工业相机做了一个**最简单的**红色装甲板检测，在 PC 上算出世界系目标，经 RoboLink 发给 MCU，让云台在"开自瞄 + 按住开火"时跟着装甲板转。目的是验证从相机到云台的整条链路可行，并看云台这一侧还差什么。识别算法只求能用，不在本次优化范围内。

## 结论

- **整条链路可行**：相机 → 检测 → 世界系目标 → RoboLink → 仲裁 → 云台。
  - 检测率 92–95%；
  - 装甲板静止时，接管后约 0.3 s 收进 0.3° 以内；
  - 装甲板移动时云台跟得上。
- **云台跟移动目标会落后 1–2°**，随目标角速度增大（下表）。主要原因有两个：
  - PC 只发目标角度、没发角速度，云台只能靠角度误差推着走；
  - yaw 角度环只有 kp 8。
- 按住开火时接管偶尔断开，几乎都是那一刻检测丢了（PC 目标无效），不是云台或仲裁的问题。
- 改进方向见最后一节。最先做的是 **PC 端发目标角速度**（不改固件），其次是第 8 步的 LQR + ESO。

## 条件

| 项 | 值 |
|---|---|
| 相机 | 海康 MV-CS004-10GC，GigE，720×540，BayerRG8，曝光 3 ms，增益 0。装在云台上，跟着枪管转 |
| 网络 | 电脑网口 `eno1` 用 NetworkManager 建链路本地连接 `gige-cam`（169.254.34.144），相机 169.254.114.9 |
| 驱动 | Aravis 0.8.36，源码编译进 micromamba 环境 `vision`（用户目录，不用 sudo）；OpenCV 5.0.0 |
| 取图 | 100 fps；接收缓冲自动、丢包重传；**每次只取缓冲里最新的一帧**（处理约 86–93 fps，比出图慢，否则延迟越积越大） |
| 固件 | infantry_dm_mc02 `180899b`（含仲裁外推 `bc90450`、重力前馈 −0.046 N·m），PID 是 `params.hpp` 里的点亮值 |
| PC 程序 | `armor.py`（检测）、`camera.py`（取图）、`aim.py`（换算与收发，复用 `tool/robolink/link_probe.py` 的 RoboLink 收发）。存在仓外的存档 `foray_mcu_archive/2026-11-06_vision_test/`，没有进仓库 |

**检测（简单版）**：

- 找红色的竖长连通域，条件是 R − B > 70 且 R > 120。红灯过曝会从红变橙再变黄，G 升高但 B 一直低，所以只比 R 和 B。
- 闭运算补上过曝发白的灯芯。
- 两根灯条按长度、倾角、高度相近，水平间距为灯条长 1–5 倍来配对，中点就是装甲板中心。

**换算**：相机随云台转，所以

- 目标 yaw = 云台 yaw − atan((u − cx)/fx)；
- 目标 pitch = 云台 pitch + atan((v − cy)/fy)。

云台姿态取 RoboLink 发来的 `GIMBAL_ATTITUDE`，按"收到图像的时刻 − 15 ms"在姿态历史里找最近的一份。只有看到装甲板、而且偏离画面中心不超过 12° 时才发目标（flags bit1），否则发"目标无效"。

**焦距标定**：电机不出力，用手转云台约 20°（yaw）、10°（pitch），同时记录装甲板的像素位置和 IMU 姿态，拟合 u = cx + fx·tan(Δyaw)：

- **fx ≈ 925 像素**（R² 0.998，残差约 3 像素），**fy ≈ 962 像素**（R² 0.98）；
- 符号与云台约定一致；
- 折算镜头约 6 mm，水平视场约 42°。

fx 和 fy 差 4%，可能是相机离转轴有一段距离带来的视差，或者镜头畸变，验证够用。

## 结果

第二轮测试 2 分钟，接管 39 次。另外每约 0.8 s 经 EmberProbe 记录一次仲裁状态，两份记录按云台 yaw 对齐。

| 情况 | 表现 |
|---|---|
| 装甲板静止，接管后 | 约 **0.3 s** 收进 0.3° 以内；之后剩 x 约 −0.2 ~ −0.3°、y 约 0° 的固定偏差 |
| 目标 yaw 角速度 0–2 °/s | 平均不落后，RMS 1.2°（主要是检测抖动） |
| 2–5 °/s | **平均落后约 1.0°**，RMS 2.9° |
| 5–10 °/s | 落后约 1.5°，RMS 3.2° |
| 10–40 °/s | 落后约 2.1°，RMS 3.7° |
| 按着开火却没接管（采样 15 次） | 14 次是 PC 目标无效（那一刻没检测到），1 次是采样正好落在跳变上 |
| 力矩 | 1 N·m 限幅在这些速度下不是瓶颈，只在手快速甩动装甲板时偶尔打满 |

**落后量和估算一致**：只有角度环时，稳态落后约等于"目标角速度 ÷ 角度环 kp"，再加上视觉延迟乘以速度。yaw 的 kp 是 8，视觉延迟按 40 ms 算（这是改成只取最新帧之前、标定时估的，改了以后应该更小，没有重新测）：3.5 °/s 时估计落后约 0.6°（实测 1.0°），7.5 °/s 时估计约 1.2°（实测 1.5°）。

第一轮测试里出现的周期性方波，是负责人一按一松弹性开关造成的。17 次接管里，每次松开云台都停在原地，行为正确。

## 过程中发现、已处理的问题

| 问题 | 处理 |
|---|---|
| conda-forge 没有 Aravis | 用 conda 装依赖，源码编译 Aravis。编译这一步被 Claude Code 的自动安全检查拦下（"运行外部代码"），由负责人在终端里执行 |
| 新版 conda-forge 的 libxml2 拆成了运行库和开发包，meson 找不到 `libxml-2.0.pc` | 补装 `libxml2-devel` |
| 红色灯条显示成蓝色 | OpenCV 的 Bayer 命名和 GenICam 差一位：GenICam 的 `BayerRG8` 要用 `COLOR_BayerBG2BGR` |
| 正对相机的灯条过曝发黄，被"R 比 G、B 都大"的条件漏掉 | 改成只比 R 和 B |
| 只按"亮"找灯条时，照片的白底被当成一个大块 | 改成按红色找 |
| 处理比出图慢，延迟越积越大（标定时算出图像比姿态晚约 40 ms） | 每次只取最新的一帧 |
| 画面里有多块装甲板时偶尔配错 | 靠 12° 的保护挡住了，没发出去。正式视觉要靠板面图案、数字来区分，不在本次范围 |

## 改进方向（云台这一侧）

按收益从大到小排：

1. **PC 发目标的世界系角速度**（不改固件，最先做）：
   - 从连续几帧估计目标角速度（比如对最近 50–100 ms 的世界系目标做线性拟合），填进控制快照的 `gimbal_yaw_rate` / `gimbal_pitch_rate`；
   - 云台把它当角速度前馈，仲裁也会用它把目标外推到当前时刻（`bc90450`）；
   - 预计能消掉大部分"速度 ÷ kp"那一项落后。正式的视觉程序也应该这样发。
2. **第 8 步：`AxisLoop` 换成 LQR + ESO**：
   - yaw 现在的 PID 角度环只有约 8 rad/s，当时为了避开猛抖才压低。辨识出 yaw 的 J 只有 0.003 kg·m²，猛抖的根子是同步带的延迟（约 8.7 ms）加上力矩打满。
   - 按辨识结果，yaw 可以给到 ω_n 15–20，响应快一倍左右；ESO 加摩擦前馈还能补掉静止时的小幅爬行（约 0.2°），缩短 0.3 s 的收敛时间。
   - 起步值见 note3（pitch ω_n 30 / ω₀ 60，yaw ω_n 15 / ω₀ 30）。
3. **角加速度前馈**（note3 第三部分，要算法组配合）：快速机动、目标变速时才有明显收益，排在 1、2 之后。
4. **视觉延迟**：
   - 本次按"PC 收到图像的时刻 − 15 ms"这个固定值找对应的姿态，实际延迟没有单独测。正式做时最好用相机的硬件时间戳或曝光触发来对齐。
   - 发出去的目标是"图像那一刻"的位置，角速度前馈加上外推能把它推到当前时刻。
5. **光轴与枪管对齐**：那 0.2–0.3° 的固定偏差，多半是相机光轴和枪管不平行，属于安装标定（可以在 PC 端加一个固定偏置），不是控制问题。
6. **目标丢失时的行为**：现在丢失 60 ms 后 PC 发"无效"，仲裁放开、云台原地停住，安全但会断续。可以考虑短时（几十 ms）按角速度继续外推，再放开。要和视觉组一起定，不能让 MCU 自己猜太久。

## 复现

```bash
# 网口（一次）
nmcli connection add type ethernet ifname eno1 con-name gige-cam ipv4.method link-local ipv6.method disabled
nmcli connection up gige-cam
# 环境：micromamba 环境 vision（python 3.12、pygobject、opencv、numpy、glib、libxml2、libxml2-devel、meson、ninja、
# gobject-introspection、c-compiler），再源码编译 Aravis 0.8.36：
#   meson setup build --prefix=$V --libdir=lib -Dviewer=disabled -Dgst-plugin=disabled -Dusb=disabled \
#     -Dpacket-socket=disabled -Dtests=false -Dintrospection=enabled -Ddocumentation=disabled && ninja -C build install
# 运行（脚本在存档里）
~/.local/share/mamba/envs/vision/bin/python aim.py --calibrate --seconds 60   # 只记录，不发目标（标定用）
~/.local/share/mamba/envs/vision/bin/python aim.py --aim --seconds 120         # 发目标：开自瞄、按住开火才接管
```

数据（标定、两轮测试、仲裁状态记录）、截图和脚本都在 `foray_mcu_archive/2026-11-06_vision_test/`。
