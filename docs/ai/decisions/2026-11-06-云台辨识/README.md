# 2026-11-06 步兵小云台模型辨识（Decision-20261106-01 第 7 步）

在 PID 闭环下给两个轴做正弦扫描与手动快推，用 `tool/control/identify_axis.py` 回归出 J、摩擦、重力与延迟，作为第 8 步 LQR + ESO 的 b₀ 与带宽依据。点亮、安全门与 PID 的过程见 `2026-11-06-云台点亮上板/`。

## 条件

- **机构**：两台 DM-J4310，都在 CAN1。pitch 输出轴直连；**yaw 经同步带传动**，约 1:1。IMU 装在 pitch 上，轴映射 source {1, 0, 2}、sign {−1, 1, 1}。
- **固件**：infantry_dm_mc02 Release `dcbe725`，用的是 `params.hpp` 里的 PID，总限幅 1 N·m，重力前馈 0。
- **激励**：
  - 扫描：`link_probe.py --sweep`，PC 以 1 kHz 发目标，自瞄接管。这个工具录制当天修过两处 bug（`d4be485`）。
  - 手动：右摇杆快推。
- **录制与导出**：每段 4000 条，1 kHz。经 EmberProbe 工作区 skills 脚本触发（写 `capture_.request`）并导出，每次 32 条。编排脚本是存档里的 `scripts/ident/segment.py`。
- **数据**：完整 13 段在仓外的 `foray_mcu_archive/2026-11-06_gimbal_identification/captures/`；每轴三段精简后放在 `test/data/gimbal/`。
- **录制前出过一次问题**：yaw 同步带松动，在点亮时的猛抖里跳齿约 66°。负责人拉紧后，在正前方重新设了零点（停核注入 SAVE_ZERO，复位后读数 −0.01°）。yaw 的数据都是拉紧以后录的，录完核对没有再跳齿。

## 结果

回归式与方法见 `tool/control/README.md`。延迟扫 0–15 拍。

| 量 | pitch（P2–P5 合并） | yaw（Y2–Y5 合并） |
|---|---|---|
| J | 0.00370 kg·m² | 0.00293 kg·m² |
| b₀ = 1/J | 270 | 342 |
| 延迟（插值后；减半拍约为物理延迟） | 4.74 拍（约 4.2 ms） | 9.15 拍（约 8.7 ms） |
| ω₀ 上限 0.5/(延迟 + 0.5 ms)（不减半拍，偏保守） | 95 rad/s | 52 rad/s |
| 库仑摩擦 Fc | 0.091 N·m | 0.085 N·m |
| 粘滞 B（不可靠） | 0.019 | 0.188 |
| 重力 G / 常值 c | G = −0.046 N·m | c = −0.013 N·m |
| R² / 残差 RMS | 0.754 / 0.139 N·m | 0.804 / 0.128 N·m |

**交叉验证（第 7 步的验收）**：

| | 只用 MANUAL 段拟合的 J | 和合并拟合的差别 | 用合并模型预测 MANUAL 段的 R² |
|---|---|---|---|
| pitch | 0.00347（P6） | −6% | 0.71（P6 自己拟合 0.73） |
| yaw | 0.00313（Y6） | +7% | 0.59（Y6 自己拟合 0.86） |

两轴的 J 都相差不到 10%，满足要求。yaw 预测的 R² 偏低，是因为摩擦不是线性的：扫描速度不超过 1.3 rad/s 时拟合出 B ≈ 0.19，Y6 里速度到了 4 rad/s，B 只有 0.08。ESO 只用 b₀，摩擦当扰动去估，不影响。

**单段的趋势**：

- pitch 的低频段 J 偏小（0.5 Hz 0.0021、2 Hz 0.0024、4 Hz 0.0043）。低频激励弱，惯性项被摩擦和噪声淹没，又有闭环偏差，所以以合并结果为准。
- yaw 各频率的 J 一致（0.0028–0.0030）。

## 对第 8 步的建议

- **b₀**：pitch 取 270，yaw 取 340。ESO 对 b₀ 的容忍度约 ±30%（note3 仿真），这里的不确定度在 ±10% 左右。
- **ω₀ 按轴给**：
  - pitch 上限约 95 rad/s，起步 50–60；
  - **yaw 上限约 52 rad/s，起步 30**。note3 原定的统一起步值 ω₀ = 100 对 yaw 不成立。yaw 的延迟大，来自同步带的弹性，点亮时的振荡频率（24 Hz，pitch 是 49 Hz）也是这个原因。
- **ω_n**：受延迟限制，pitch 先 30，yaw 先 15–20，上板再加。
- **重力前馈**：G = −0.046 N·m，和参数里的 0 差得明显，按 note3 单独一个 `params:` 提交填进 `pitch_gravity_newton_meter`。量级比摩擦还小，PID 下效果有限。
- **摩擦前馈**：起点取 Fc ≈ 0.09 N·m。yaw 有明显的粘滞成分，而且随速度变，先只用库仑那一项。

## 录制中发现、已处理的问题

| 问题 | 处理 |
|---|---|
| `link_probe.py` 带扫描或目标启动就崩（`t0` 未赋值）；扫描值过不了标准帧的 float32 精确检查 | `d4be485` |
| `identify_axis.py` 只扫 0–5 拍，yaw 的 9 拍超出范围，pitch 的峰值压在边上；没有可用样本时 `KeyError` | `1aafe44`：扫到 15 拍、加 `--max-delay`、峰值在上限时提示；没有可用样本时说明原因 |
| PC 帧之间目标是阶梯、帧晚到补上时目标跳变，云台的目标平滑把前馈打到上限，单点力矩尖峰（约 0.1%） | `bc90450`：仲裁按 PC 角速度外推目标，最多 20 ms。**录制数据是改之前录的** |
| `params.hpp` 写着 yaw "输出轴直连" | `5aa1d30`：改为同步带，写上跳齿的现象与处理办法 |
| yaw 同步带跳齿约 66° | 负责人拉紧，在正前方重新设零点 |
| EmberProbe 用扩展目录里的脚本会弹出超出屏幕的批准框；`std::array` 不能切片；每次最多读 32 个对象 | 改用工作区 `.agents/skills/` 里的脚本，逐个元素读，每次 32 条。写进了负责人的辨识流程笔记（note4） |

## 外推的上板复核（2026-11-06 晚）

用 EmberProbe 烧录 `180899b`（含 `bc90450` 的外推与 −0.046 N·m 的重力前馈），ELF SHA-256 前 16 位 `3d9eecf2064cf85f`，EmberProbe 报 `match`。按 P5 的条件（pitch ±0.15 rad、4 Hz）重录一段：

| | P5（`dcbe725`，不外推） | P5b（`180899b`，外推） |
|---|---|---|
| 单点力矩尖峰（偏离 11 点中位数 > 0.4 N·m） | 57 个（1.43%） | 14 个（0.35%） |
| 力矩打满（\|τ\| > 0.98 N·m） | 1.12% | 0.18% |
| 25 点平滑后的力矩峰值 | 0.74 N·m | 0.74 N·m |
| 角度幅值 | 9.89° | 9.81° |
| 单段回归 R² / J | 0.834 / 0.0043 | 0.848 / 0.0043 |

- 尖峰少了约 3/4，打满少了约 5/6，跟踪本身没有变化。
- 剩下的尖峰大多在力矩本来就接近 ±0.9 的峰顶附近，是噪声叠加，不是目标跳变。
- 单段的 G = −0.039 N·m。现在下发力矩里含了重力前馈，回归出的 G 照样是托住需要的总力矩，和 −0.046 在误差范围内。

数据在存档的 `captures/pitch_p5b_sweep_4hz_extrap/`。
