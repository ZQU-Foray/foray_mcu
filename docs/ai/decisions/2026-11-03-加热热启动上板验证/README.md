# 加热控制器热启动修正的上板验证（2026-11-03）

> Decision-20261103-02。原始记录在仓库外：`/mnt/data/projects/foray_mcu_archive/2026-11-03_heater_warm_start/`（`SHA256SUMS`）。

## 固件

- `link_dm_mc02` Release，基于 `b25273d`（加热修正）；
- 叠加当时工作区里未提交的 VQF 静止零偏调参（Decision-20261103-03，另一边的工作，补丁存为 `worktree_on_b25273d.patch`）；
- `.bin` 的 sha256 以 `10ccf3f0` 开头。

烧录前照例只读备份两遍，两遍一致。板上原来的固件不是 `fa3e0d3`，是另一边调参时烧的。

## 结果

读数用 SWD 不停核读出，每 3 s 一次（`after_flash.txt`、`warm_reset_50.txt`）。

**烧录引起的复位**（板子约 49 ℃）：
- 环境估计从开机读数起步，12 s 内降到 37.2 ℃；
- 温度回到 50 ℃，最高 50.375 ℃；
- 之后 IMU 进入 READY。

**恒温 50 ℃ 时直接复位**（最坏情况：开机读数就是目标温度，环境估计 50.06 ℃）：

| 复位后 | 状态 |
|---|---|
| 3–12 s | 维持功率按估高的环境算得太小，读数掉到 48.1 ℃；读数低于"加热器一直关着"的预测，环境估计开始下调 |
| 18 s | 环境估计 37.4 ℃（不加热时板子约 38–40 ℃） |
| 21 s | 回到 50 ℃，最高 50.375 ℃，之后在 50.0–50.375 ℃ |
| 69–72 s | 温度稳定满 20 s，零偏标定取窗口，IMU 进入 READY |

修正前同样的情况卡在 48 ℃，IMU 一直停在 SETTLING（[RoboLink 对账记录](../2026-11-03-RoboLink-对账/README.md) §5）。

**之后的链路**（`probe_30s.txt`）：
- 握手 0.6 ms；30 s 没有 CRC、帧头、槽位错误，帧序号连续；
- 姿态 996 Hz，样本停留中位 43 µs；
- READY 后 30 s 里 yaw 变化 -0.1°（约 -0.2 °/min）。
