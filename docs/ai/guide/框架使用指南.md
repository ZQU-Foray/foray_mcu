# 框架使用指南（foray_mcu）

> AI 撰写（2026-11-01），对应架构 v2.10（[architecture.md](../architecture.md)）与 Decision-20261101-01～03。
> 读者：要在本框架上加外设、驱动、topic、能力、profile 或新板的人。规则的出处见架构文档，这里只讲怎么做。
> 例子都取自仓库里现成的代码，可以对照着看。

## 0. 一张图

```text
config/assembly/<profile>.cpp      组合根：构造对象、注入句柄与参数、任务表、boot_*
  ├─ config/profiles/<profile>/    profile.cmake（板、能力）+ params.hpp（只含数据）
  ├─ platform/<厂商>/<板>/board/board.hpp  板上的物理资源句柄（只有组合根与 port 能看到）
  ├─ app/common/                   任务运行器（只有它和组合根用 FreeRTOS）
  └─ app/<能力>/                   能力：init(Config)/step(now)，零 RTOS，只经 topic 互相通信
       ├─ app/topics/              全部 topic 的清单
       └─ src/                     框架：driver → hal 契约；lib；middleware（topic）；utils
platform/<厂商>/<板>/port/         hal 与 hal/os 契约的实现（C++，每个外设一个 .cpp）
platform/mock/                     同一套契约的宿主替身（测试用）
```

依赖只能从上往下。看不见的头 include 不了（CMake 的 PRIVATE include），看得见但不该用的由 `tool/ci/arch_check.py` 拦（规则 1–18）。

## 1. 加一个外设接口（hal 契约）

以 `hal::Can` 为例（`src/hal/can.hpp`、`platform/st/dm_mc02/port/can.cpp`、`platform/mock/mock_can.cpp`）。

1. **契约头** `src/hal/<外设>.hpp`：一个句柄类。
   - 只有一个私有成员 `std::uint8_t index_`，`constexpr explicit` 构造；
   - 结果、帧等类型收在类里，用 `enum class` 与 POD；
   - 成员函数全部 `const noexcept`，返回值要检查的加 `[[nodiscard]]`；
   - 每个函数的注释写清：任务还是中断里调用、阻不阻塞、必选还是可选（可选的不支持时返回 `UNSUPPORTED` 或 `false`）；
   - 回调用 `hal::Callback`，时间用 `hal::os::Microseconds`；
   - 只 include 标准库头与 `hal/` 下的头，不能出现厂商、CMSIS、FreeRTOS 的名字，注释里也不行（规则 3）。
2. **port** `platform/<厂商>/<板>/port/<外设>.cpp`：实现成员函数。
   - 外设表的下标就是句柄编号；表按初始化列表推导长度，`static_assert` 与 `board.hpp` 的个数核对：
     ```cpp
     const std::array HANDLES{&hfdcan1, &hfdcan2, &hfdcan3};
     static_assert(std::tuple_size_v<decltype(HANDLES)> == board::CAN_COUNT, "表长必须与 board.hpp 一致");
     ```
   - 先检查编号（`index_ >= 表长` 返回无效参数），再检查状态；
   - 与中断共享的状态在 `hal::os::CriticalSection` 里读写；中断写、任务读的字节或帧用 `concurrency::SpscQueue`；中断通知用 `port::Notifier`；
   - **覆盖 HAL 回调的 .cpp 必须 include 对应的 HAL 头**（如 `fdcan.h`），否则回调被 C++ 改名，HAL 的弱实现照旧生效，编译链接都不报错（规则 16，CI 的回调检查会抓到）；
   - 需要初始化的，在 `port.hpp` 声明 `port::init_<外设>()`，加进 `hal_init.cpp` 的 `hal::init()`；
   - 源文件列进板级 `CMakeLists.txt` 的 `port_<板>`。
3. **board.hpp**：给出句柄、个数、能力常量，注释写清每个资源接在哪、能做什么：
   ```cpp
   inline constexpr hal::Can CAN_1{0U};
   inline constexpr std::uint8_t CAN_COUNT{3U};
   ```
4. **mock** `platform/mock/mock_<外设>.cpp`：实现同一组成员函数，参数检查与结果的优先级和 port 一致；在 `mock_hal.hpp` 加测试控制接口（`mock::<外设>::reset()`、注入输入、读出输出）。回调在锁外调用。
5. **测试** `test/host/unit/hal/<外设>_test.cpp`：把契约的语义测一遍（替身就是驱动测试的依据）。列进 `test/host/CMakeLists.txt`。
6. `src/CMakeLists.txt` 的 `hal` 列表加上新头。

## 2. 加一个驱动

以蜂鸣器为例（`src/driver/buzzer/`）。

- 放 `src/driver/<设备>/`，命名空间 `device`，target `driver_<设备>`（`framework_library()`）。
- **句柄在构造时注入**，按值保存；构造函数是 `constexpr`，全局对象常量初始化：
  ```cpp
  class Buzzer final
  {
    public:
      constexpr explicit Buzzer(hal::Pwm pwm) noexcept : pwm_{pwm} {}
      [[nodiscard]] Result play(std::uint32_t frequency_hz, std::uint8_t volume) noexcept;
    private:
      hal::Pwm pwm_;
  };
  ```
- 只依赖 `hal`、`hal/os`、`lib`、`utils`、其他驱动；不依赖 `middleware`（不发布 topic）、`app`、RTOS（§2.3）。
- 驱动不做跨任务同步：一个驱动对象只在一个任务里用。要给别的能力用的数据，由持有它的能力发布 topic。
- 要求可选能力的，给出编译期常量让组合根检查（`device::Bmi088::REQUIRES_SPI_ASYNC`）；能回退的在运行期回退（`Ws2812` 遇到 `UNSUPPORTED` 改用阻塞发送）。
- 接收队列只有一个消费者的外设（CAN、UART），驱动在 `init()` 里占住（`hal::Can::claim_receiver()`），失败时不占用。
- 时间一律 `hal::os::now_us()`，字段名带 `_us`。
- 不写 `#if`（规则 9）；不用原子读改写（规则 13）；float 不要隐式提升成 double（规则 14）。
- **测试**：链接 `platform_mock`，用 `mock::` 接口注入与检查。例子：`test/host/unit/buzzer/buzzer_test.cpp`、`test/host/unit/motor/dji_motor_test.cpp`、`test/host/unit/imu_acquisition/bmi088_acquisition_test.cpp`（用 SPI 应答函数扮演 BMI088）。

## 3. 加一个 topic

约定见 [app/topics/README.md](../../../app/topics/README.md)。要点：

- 按发布者所属的能力分文件：`app/topics/<能力>.hpp`，命名空间 `topics::<能力>`，名字字符串 `"<能力>.<topic>"`；
- 消息：可平凡拷贝，只用标准整数、浮点、`bool` 与 `std::array`，不超过 64 字节；要时刻的放 `timestamp_us`；
- 实例 `inline topic::Topic<消息> 名字{"能力.名字"};`，并加进 `app/topics/all.hpp` 的 `ALL`；
- 每个 topic 只有一个发布者（`claim_publisher()` 只成功一次）；新头列进 `app/CMakeLists.txt` 的 `app_topics`。

## 4. 加一个能力

以 `bringup::ImuCheck` 为例（`app/bringup/imu_check.*`）。

- 放 `app/<能力>/`，target `app_<能力>`（`app_library()`），命名空间与目录同名；新目录先加进白名单（架构 §5.4，`arch_check.py` 的 `WHITELIST`）。
- 对外只有三样：
  ```cpp
  struct Parameters { /* 只含数据：profile 的 params.hpp 给值 */ };
  struct Config { device::Bmi088 *imu; hal::Gpio gyro_interrupt; /* …组合根注入的依赖… */ Parameters parameters; };
  [[nodiscard]] bool init(const Config &config) noexcept; // 取得发布句柄、占等待槽、登记中断回调
  void step(hal::os::Microseconds now) noexcept;          // 任务每轮调用
  ```
- 能力零 RTOS：不 include FreeRTOS，不建任务，不阻塞；线程由组合根的任务表决定。
- 能力之间只经 topic：不 include 别的能力的头（规则 18）。
- **中断里只做取数据与发布**。回调在框架中断里执行，更新状态与取快照放在临界区里，发布放在临界区外（发布要叫醒等待者，`Signal::notify()` 不能在临界区内调用）：
  ```cpp
  void ImuCheck::publish_event(bool accel, bool gyro, bool transfer) noexcept
  {
      topics::bringup::ImuEvent snapshot{};
      {
          const hal::os::CriticalSection guard;
          /* 更新计数与时刻 */
          snapshot = interrupt_state_;
      }
      event_publisher_.publish(snapshot);
  }
  ```
- 订阅：`topic::Subscriber<消息> 名字{topics::…};` 作成员，`update()` 读新数据。
- **测试**：直接调用 `init()`、`step(now)`，用 `mock::set_now_us()` 控制时间，`mock::gpio::trigger_interrupt()` 模拟中断。例子：`test/host/unit/bringup/imu_check_test.cpp`、`io_checks_test.cpp`。同一个进程里每个 topic 只能取一次发布句柄，多个测试共用时在 `main()` 里取一次再传下去。

## 5. 加一个 profile（兵种 × 板）

以 `bringup_dm_mc02` 为例。

1. `config/profiles/<兵种>_<板>/profile.cmake`：`PROFILE_ID`（与目录同名）、`BOARD`、`CAPABILITIES`（链接哪些 `app_<能力>`）。
2. `params.hpp`：只含数据，只能 include 能力的头与标准库头（规则 4，文本扫描检查）：
   ```cpp
   inline constexpr bringup::ImuCheck::Parameters IMU{device::Bmi088::Config{}, estimate::IDENTITY_AXIS_MAPPING,
                                                      1000U, 200U, 50.0F};
   ```
3. 组合根 `config/assembly/<profile>.cpp`：
   - 用 `board.hpp` 的句柄构造驱动，构造能力；
   - 可选能力的编译期检查：`static_assert(!device::Bmi088::REQUIRES_SPI_ASYNC || board::SPI_ASYNC, "…");`
   - 任务表 `constexpr std::array<common::TaskSpec, N> TASKS`：名称、栈（字）、优先级、触发（`every_ms`、`on_topic`、`on_topic(topic, 超时)`）、step 列表（普通函数，每个调一个能力的 `step(now)`）；写错的任务表编译不过；
   - `boot_init()`：`hal::init()`，再按依赖顺序调各能力的 `init()`，最后 `g_runner.init()`；`boot_init_rtos()`：`g_runner.start()`；`boot_run()`：`g_runner.sample_stack_health(now)`。
4. 构建：`cmake -S . -B build/<目录> --toolchain cmake/toolchains/arm-gcc-cortex-m7.cmake -DPROFILE=<名称>`（preset 默认是 bringup）。

## 6. 加一块板

1. `platform/<厂商>/<板标识>/`：`board.cmake`（`BOARD_ID`、`BOARD_CPU`、烧录配置）、`CMakeLists.txt`（生成区、`port_<板>`、`board_<板>`、`os_freertos_<板>`，port 与 board 必须是 OBJECT 库）。
2. `cubemx/`：生成物，只在 USER CODE 区调 `boot_*`（规则 7）。外设中断的优先级不要高于框架线（FreeRTOS 的 `configMAX_SYSCALL_INTERRUPT_PRIORITY`），否则 port 的临界区屏蔽不了它们。
3. `port/`：hal/os（时基、临界区、`Signal`）与 hal 各外设的实现，`hal::init()`。
4. `board/board.hpp`：这块板的句柄与能力常量。驱动与能力不用改。
5. 把板标识加进 `arch_check.py` 的 `BOARD_WHITELIST`（新厂商还要加进 `platform` 的一级白名单；先在 decision.md 登记）。profile 的 `BOARD` 写 `<厂商>/<板标识>`。

## 8. 常见的坑

| 现象 | 原因 | 办法 |
|---|---|---|
| HAL 回调没被调用，编译链接都正常 | 定义回调的 .cpp 没 include HAL 头，函数被 C++ 改名 | include 对应 HAL 头；CI 的回调检查会报 |
| 回调在静态库里"消失" | port 做成了 STATIC 库，链接器没拉进强符号 | port 与 board 用 OBJECT 库 |
| 固件卡死在 `configASSERT` | 在临界区内调用了 `Signal::notify()`（发布 topic 会调用它） | 发布放在临界区外 |
| 中断里用 topic 偶尔读到旧值或卡住 | 中断优先级高于框架线 | 框架线以上的中断不用框架，只能自己处理数据再转交 |
| 第二个电机组 `init()` 失败 | 同一条 CAN 总线的接收只能被占用一次 | 一条总线一个接收方；不同产品线分总线 |
| `params.hpp` 编不过或被扫描拦下 | include 了 `board.hpp`、驱动或契约头 | 依赖在组合根注入，`params.hpp` 只放 `Parameters` |
| 嵌套结构作默认参数编译报错（"default member initializer required before the end of its enclosing class"） | C++ 的限制 | 分成两个重载（如 `Bmi088::init()` 与 `init(const Config &)`） |
| 全局对象占了 Flash 初值（`.data`） | 对象里有非零初值 | 大对象尽量全零初值，在 `init()` 里赋值（任务运行器就是这样放进 `.bss` 的） |
